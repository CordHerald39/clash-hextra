要确认某个参数在 Clash 电脑端是否适用，应当以仓库说明和发布页中的版本、平台、通道和当次变更为条件，而不是以参数“看起来像 Clash 配置”为条件。官方说明给出的是安装包范围、发行通道含义、功能模块清单，以及每个标签对 DNS、Merge、Script、服务、TUN 等路径的修正。参数只有落在这些条件内，才谈得上在本机使用。

## 适用条件

本方法适用于：参数来自教程、订阅片段或旧文件，需要判断能否用于本机 Clash Verge Rev。需要同时满足：能访问 https://github.com/clash-verge-rev/clash-verge-rev 与 https://github.com/clash-verge-rev/clash-verge-rev/releases ；知道本机系统、架构和安装包文件名中的版本。缺少任一项，只能得出条件不足、不能确认适用，不能得出参数正确。

仓库写明支持 Windows（x64/x86）、Linux（x64/arm64）、macOS 11+（intel/apple）。发布页补充 Windows 不再支持 Win7，并区分普通安装包与 `fixed_webview2` 包。参数文本再完整，系统或安装包变体不满足时仍不适用。订阅相关说明若需举例，只写 `token=示例` 这类参数片段。

## 从官方说明里抽取条件的步骤

读仓库“我应当怎样选择发行版”。Stable：正式版，高可靠性，适合日常使用。Alpha：测试发布流程，已废弃。AutoBuild：滚动更新，适合测试反馈，可能存在缺陷。参数适用条件首先是通道：日常使用应对齐 Stable；文档只给 AutoBuild 或废弃 Alpha 时，该参数不能直接视为适用于正式版。

读仓库功能说明：基于 Rust 与 Tauri 2；内置 Clash.Meta(mihomo) 并可切换 Alpha 内核；配置管理与 Merge、Script；系统代理与守卫、TUN；可视化节点与规则编辑；WebDav 备份。将参数归入其中一类。无法归类则缺少官方适用条件，应视为未确认，而不是默认可用。

在发布页用本机版本对齐标签。阅读该标签的修复与优化，查找该参数所属主题是否被改过适用边界。例如 DNS 覆写按订阅独立记忆、空内容与空字段处理、Merge 与 Script 的覆盖关系、应用设置优先于扩展写入、服务协议不兼容需重新安装。这些句子就是参数的附加条件。

读平台分段。同一参数在 Windows、macOS、Linux 上的前提可以不同。官方以分段标题标明范围，未出现在本机平台分段中的前提，不能从其他平台条目推断成立。再用安装包文件名核对架构：x64 与 arm64 不可互换；macOS 的 aarch64 与 x64 对应不同芯片；Linux 还需区分 deb、rpm 与 amd64、arm64、armhf。架构不符则安装说明中的功能条件全部不成立。

判断“适用”的依据：通道为文档所针对的通道；标签一致或已消化差异说明；平台与架构匹配；参数能归入功能列表或该标签说明中的主题；没有被“由应用设置接管因而丢弃”一类说明排除。

## 参数被官方说明排除或收窄时如何判定

发布说明出现过扩展配置或脚本写入由应用设置接管的字段时，值被丢弃并记入扩展日志。此时该参数在订阅或脚本中的写法不具备适用条件，即使文本结构合法。DNS 相关参数要看是否启用覆写、是否针对当前订阅；自动关闭仅影响当前订阅，不能把某一订阅上的开关状态当成全局条件。

订阅与规则集合的参数还受更新过程影响。曾有响应较慢时更新误报失败且不显示真实失败原因，也有不同来源共用缓存路径导致服务模式无法启动内核。参数本身可能无误，适用条件却包括独立缓存路径与可完成的更新。服务模式与 TUN 相关参数依赖服务能启动。各标签多次修复 Windows 权限误判、服务残留、macOS 用户组解析、Linux 安装服务后仍无法启动内核等。官方适用条件包含：当前标签已覆盖本机那类故障，或服务版本与协议兼容。不满足时，TUN 或服务相关参数不适用。

## 无法确认时的下一步

官方两页都未提到该参数：停止写入本机正在使用的配置，仅保留在副本中待查；不要用第三方命名习惯补全条件。只知参数、不知版本：先按安装包文件名确定标签，再重复上述步骤。本机通道与文档通道不同：先回到 Stable 发布说明，只有文档明确针对 AutoBuild 且本机也是 AutoBuild 时才继续。条件互相冲突时，例如文档要求扩展脚本写入某字段，本机标签声明该字段由应用设置接管，则以本机标签为准，该参数在扩展路径上不适用。
