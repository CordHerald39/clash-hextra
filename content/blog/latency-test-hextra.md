官方代理组说明没有单独提供「把每次探测过程写入独立日志文件」的字段。要把测试 URL、时间参数和网络出口放在一起备查，只能把仍生效的项写进同一策略组，并把已经改到节点侧的出口字段一并列入对照，让配置文本本身成为可核对的记录。下面按字段说明记什么、记在哪、记错了怎么查。

## 适用条件：哪些项可以算作同一条记录

可写在组上、与健康检查直接相关的项包括：`url`（测试地址）、`interval`（间隔，单位秒）、`timeout`（超时，单位毫秒）、`expected-status`（期望 HTTP 状态码）、`lazy`（未选中是否不测）、`max-failed-times`（失败几次后强制检查，默认 5）。网络出口方面，组上的 `interface-name` 与 `routing-mark` 已弃用，资料要求改用代理节点中的对应字段；策略组出站时的优先级为代理节点大于代理策略大于全局。因此「网络」不能只在组里保留一份已弃用键，否则记录与真实出站会不一致。

这条记录只对 `proxies` 内代理的组级检查有意义。`url` 不会检查通过 `use` 引入的代理集合。节点几乎全在集合里时，只在策略组这一层记录探测条件，会漏掉真正被测的那一层。`filter`、`exclude-filter`、`icon`、`hidden` 也不属于探测档案：前两者管谁进组，后两者只给使用 API 的前端适配展示。

## 把 URL、时间写进同一组，网络写到仍生效位置

第一步，在目标 `proxy-groups` 项下写入 `url`，与组 `name` 出现在同一段配置，避免地址写在别的组、时间写在本组。组名含特殊符号时用引号包裹，防止这一段记录在解析时断开。第二步，紧邻写入 `interval` 和 `timeout`，并在对照说明里标明单位分别是秒和毫秒，避免日后把 300 当成毫秒、把 5000 当成秒。资料里间隔与超时的示例量级是 300 秒与 5000 毫秒，记录时应对齐单位，而不是复制某一个业务场景。第三步，若对可用性有状态码要求，把 `expected-status` 写在同一段，采用斜线多码、短横范围或混合写法，例如 `200/302` 与 `400-503`，这样「时间到了但状态不合格」和「时间未到」可以对照同一记录解释；无要求时明确保持默认 `*`。第四步，把 `lazy` 与 `max-failed-times` 写明，记录才包含何时开始测、失败几次强制测。第五步，在真正转发的代理节点上写入 `interface-name`、`routing-mark`；多个节点出口不同时，网络记录必须落到节点，组上堆弃用字段不能称为一起记录。

不要把筛选正则当成测试 URL 的备份，也不要把 `empty-fallback`、`default-selected` 写进探测档案：前者是空组回退且只允许 proxy 名称，后者是缺省选择。

## 怎样判断记录完整，失败时下一步

完整的判断依据是：打开该策略组能同时读到地址、间隔、超时；需要状态约束时能读到 `expected-status`；需要绑网或路由标记时能在节点上读到出口字段，而不是只在组上看到弃用键；若成员来自 `use`，承认组级记录覆盖不到它们。`interval` 为 0 表示未启用定时测试，这条也必须能从同一段配置读出来，不能靠记忆补。

记录了但检查行为对不上：先核对该 `url` 是否只作用于 `proxies`。时间项看起来没生效：看 `interval` 是否为 0、`lazy` 是否因未选中跳过。网络项无效：按弃用说明改到节点并核对该优先级顺序。组为空时不要把回退代理组名写进 `empty-fallback`。需要在 API 中隐藏组或显示图标时用 `hidden`、`icon`，它们与探测记录无关。本页资料未给出把每次探测的过程行写入独立日志的配置项，因此对不上时下一步是回到同一组字段及节点出口字段逐项核对，而不是寻找未记载的日志开关。
