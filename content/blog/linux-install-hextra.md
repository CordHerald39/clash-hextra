排查 Linux 上的 Clash Verge Rev，需要留下启动命令和完整报错。仓库声明配置与日志只保存在本地。较新版本会在界面显示内核启动失败的具体原因，并把服务运行日志写入文件，同时修复了服务模式强制结束内核导致最后日志丢失的问题。这些内容必须在复现当时保存，才能对照 Release 说明。

## 适用条件

适用于首次安装后无法启动、修复或重装服务前后对比、准备提交反馈。一次成功的日常打开不必归档。记录必须在复现时产生，事后凭记忆补写容易把 GUI 提示和服务日志混在一起。

## 保存启动命令与终端输出

从图形入口启动不会自动留下命令。需要记录时，在终端启动并把标准输出、标准错误写入文件。

1. 记下工作目录、是否提升权限、完整命令。首次以管理员身份启动可导致数据目录所有权不符、服务拒绝启动内核，因此权限方式必须写入记录。
2. 用重定向或 `tee`，让屏幕和文件都有一份。命令原文与报错放在同一文件。
3. 判断依据：记录里应看到启动瞬间的完整句子。终端无输出但窗口有提示时，把窗口原文抄入。较新版本会显示内核启动失败或服务模式内核意外停止的原因，并在窗口恢复后提示尚未解决的错误。同时写上发行版摘要、`uname -m`、`.deb` 或 `.rpm` 文件名、版本标签。不要只写「启动失败」。

## 保存路径类错误与服务日志线索

1. 文件错误日志会给出具体路径和失败原因，原样抄写，并标明路径像订阅或覆写，还是程序文件。
2. 服务自身运行日志会保存到文件，用于追查内核被停止的原因。内核被停、TUN 不可用或服务模式异常时，应复制该日志。官方未给出固定路径，不要编造目录，只记录实际找到的位置。
3. 若曾强制结束内核，在记录中写明，以便判断日志是否完整。
4. 判断依据：能回答用了什么命令、屏幕完整报错、有没有服务日志。复制时自行去掉订阅 URL 等本地敏感字段，保留错误类型、路径模式和版本。项目不收集用户数据，记录只放本机。

## 记不成时下一步

终端关闭后输出消失，说明还没有重定向，用同一命令再启动并写入文件，先不要改配置。窗口提示一闪而过，先改用会保留错误提示并把服务日志落盘的版本再复现。找不到服务日志时，明确写「未找到」，同时注明是否安装过服务。按时间排列：命令、终端输出、窗口原文、文件路径错误、服务日志，再对照该版本 Release 的 Linux 与服务条目。
