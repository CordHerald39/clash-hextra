规则列表里能搜到目标域名，但连接仍走另一策略，先看它前面有什么。mihomo 按从上到下顺序匹配，顶部规则优先。多数“规则存在但没生效”的问题，需要检查更早匹配的条目与实际模式，不是把同一条规则再复制一遍。

## 精确规则和宽泛规则的先后

以下只是顺序示意，策略组 Proxy 需在正式配置中存在：

```yaml
rules:
  - DOMAIN-SUFFIX,example.com,Proxy
  - DOMAIN,docs.example.com,DIRECT
```

访问 docs.example.com 时，前面的后缀规则已经涵盖目标，后面的精确规则无法完成希望的例外。如果目标是让 docs 子域直连，精确条目应放在这条宽泛后缀之前。不是“越精确自动优先”，而是列表位置优先。

## MATCH 也是规则，不是注释

`MATCH` 无需条件，匹配所有请求，应作为没有更具体命中时的兜底。把它放在顶部，后面的域名条目通常就不会有机会执行。订阅、规则预设和覆写合并后，最终顺序可能与自己编辑的片段不同，因此应检查生效列表。

手册还说明，当 UDP 请求匹配到的节点不支持 UDP 时，可能继续向下匹配。故不能只看规则文本推断所有协议都会得到完全相同的结果；出现差异时保留网络类型信息。

## 用新连接看命中结果

先确认使用规则模式，固定目标和应用，关闭目标旧连接后重新请求。记录实际域名或 IP、网络类型、匹配规则及策略。旧连接可能仍沿用此前的出口，网页刷新也不一定让每条连接重建。

若记录没有域名，域名规则本来就缺少匹配条件，应继续检查 DNS 与域名识别；若命中另一条规则，按顺序找到遮挡点。一次只调整一个位置，保留副本，避免把整套列表翻转。
