升级 Clash Verge Rev 电脑端前，要把当前版本到目标版本之间每一份发行说明拆成可对照的条目，再按本机系统与正在使用的功能过滤。下面只说明如何核对变更，依据官方发布页与仓库说明做判断，不假设覆盖安装会自动完成任何修复。

## 什么情况下需要逐条核对

已安装该应用、能确认当前版本号，并准备到发布页选取正式安装包时，应做逐条核对。仓库把 Stable 定义为正式版、适合日常使用；AutoBuild 为滚动更新、可能存在缺陷。核对对象应是 Stable 的连续 tag，而不是只打开最新一条说明。

必须先核对再决定是否升级的情形包括：本机可能用到服务模式、TUN、系统代理、DNS 覆写、订阅或规则集合、Merge 与 Script、Sidecar；计划跨多个小版本；Windows 需要确认系统是否仍在支持范围。发布页 Windows 下载区写明不再支持 Win7，系统不在支持范围则应停止升级。

若无法确认当前版本、无法区分本机架构（64 位或 ARM64、macOS 芯片、Linux 的 DEB 或 RPM），或准备使用与 tag 对不上的滚动包，则不具备核对条件，应先补齐版本与安装包信息。

## 怎样按版本把说明拆成条目

记下当前版本与目标版本，例如从 v2.5.5 到 v2.5.7。打开发布页后，把中间全部 tag 按从旧到新排列。存在 v2.5.6 时，必须先读完 v2.5.6 全文，再读 v2.5.7。只读最新说明无法覆盖中间修复。

每一份说明通常包含「修复问题」和「优化改进」。正文常放在折叠块中，未展开时平台小节会丢失。展开后按三条规则归类：没有系统前缀的条目归入全平台；带 Windows、macOS、Linux 或 macOS/Linux 的条目只归入对应系统；下载区关于安装包形态的文字（正常版本、内置 Webview2、deb、rpm）单独列为安装条件，不与功能修复混记。

将归入本机的条目改写成是/否问题，例如：是否使用服务模式；订阅是否含自定义 DNS；是否依赖 DNS 覆写在重启后保持开启；Windows 是否涉及服务安装失败或权限误判；macOS 是否在启动、VPN 接管或手动配置网卡后使用系统代理；Linux 是否在安装或修复服务后启用内核与 TUN。能回答的标为相关，本机明确未使用的标为不相关，无法回答的标为未理解。相邻版本对同一主题的改写应合并为一条主题，避免重复计数。

最后核对该 tag 下载列表是否包含本机资产名称。列表与本机不符，说明核对未完成。

## 判断标准以及核对失败后怎么做

可以进入升级准备的依据：区间内每个 tag 的修复与优化均已展开；本机系统与架构出现在对应下载列表；相关条目均可映射到本机是否使用该功能；未理解条目为零；若条目写明升级后服务版本或协议不兼容需重新安装，或涉及数据目录所有权、残留服务进程，已把「按该版本说明处理服务」写入计划。

应当暂缓的依据：系统为 Win7 或无对应安装包；无法确认是否处于服务模式、是否启用 TUN 或 DNS 覆写；通用条目与平台条目互相引用（例如内核停止后系统代理仍指向失效端口）但本机状态不明。

核对失败时不要用猜测补全说明。条目数量与折叠块标题不符，应重新展开该 tag 全文后再计数。只看到最新 tag，应回到发布页按 tag 列表补读中间版本。说明中的常见问题链接与仓库文档入口只能用于解释同一份说明里的术语，不能替代未读的 tag。仍无法映射到本机时，保持当前版本，不要用错误架构的安装包去验证说明是否生效。
