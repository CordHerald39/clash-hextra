Windows 首次启动后要确认打开的是正确程序，依据应来自官方发布页上的包名、标签和系统限定，而不是自行猜测窗口里有哪些菜单。Clash Verge Rev 是基于 Tauri 的 Clash Meta 图形界面，官方安装包只从发布页提供，且 Windows 不再支持 Win7。

## 适用条件

本判断只适用于已经用官方 Windows 安装包完成安装、第一次打开程序的情形。系统须为官方写明支持的 Windows x64 或 ARM64，不能是 Win7。安装包须能在对应标签的资产列表中找到。若实际运行的是未出现在该列表中的文件，或把已废弃 Alpha、AutoBuild 滚动版当成正式版却不加标注，则无法按下面的标准确认「正确程序」。

还要分清包类型。正常版本（推荐）文件名形如 `Clash.Verge_<版本>_x64-setup.exe`（64 位常用）或 `Clash.Verge_<版本>_arm64-setup.exe`（ARM64 不常用）。内置 Webview2 版文件名含 `fixed_webview2`，官方写明体积较大，仅在企业版系统或无法安装 Webview2 时使用。用错架构，或在不需要时使用内置 Webview2 包，都会让「打开的是哪一次安装结果」对不上发布说明。

## 用安装身份确认程序

官方仓库把产品写作 Clash Verge Rev，并说明它是 Clash Verge 的延续、内置 Clash.Meta（mihomo）内核。首次启动前，先把你运行的快捷方式或可执行文件，回溯到当时所用的 setup 文件名和发布标签（例如 v2.5.7）。能同时确认「标签在发布页存在、文件名与该标签 assets 逐字一致、仓库路径为 `clash-verge-rev/clash-verge-rev`」，才能把这次启动记成官方程序。

不要用其他 Clash 图形界面顶替对照。仓库致谢中列出的 zzzgydi/clash-verge、Fndroid/clash_for_windows_pkg 是不同项目。仅名称含 Clash、界面风格相近，不足以证明打开的是 Clash Verge Rev。官方资料没有给出窗口标题或关于页的逐字文案，因此不要编造菜单路径去「看版本」；版本应对回发布页的 `tag_name` 与安装包文件名中的版本号（如 2.5.7）。

## 首次启动现象不要误判成程序不对

Windows 发布说明记载过若干刚安装或第一次启动时的表现。它们说明的是官方程序在特定条件下的行为，不能单独用来断定打开了假程序：

- 部分系统安装服务失败时可能提示「program not found」（v2.5.7 记为已修复）。
- 服务安全检查未通过时，较新版本会说明原因并提供修复文档链接，而不是只显示「服务无法启动内核」。
- 未安装服务、以普通权限运行时，曾出现内核无法启动（v2.5.6 记为已修复）。
- 服务已停止时，曾出现启动后约两分钟才显示窗口（v2.5.6 记为已修复）。
- 首次以管理员身份启动后，系统服务可能因数据目录所有权不符而拒绝启动内核（v2.5.5 记为已修复）。
- 内核未运行时，首页仍显示服务模式曾被记为缺陷（v2.5.5 记为已修复），不能单凭该首页状态认定程序身份。

判断依据是：安装身份已与官方资产对应，同时启动提示的措辞能与上述发布说明对照。提示对得上，应进入失败处理，而不是改去运行来路不明的另一个「Clash」。提示完全对不上官方记载、且安装包也不在资产列表中，则不能确认是正确程序。

## 失败时下一步

安装包文件名或版本号无法在对应标签 assets 中找到：不要继续把当前进程当作官方程序，回到发布页按 Windows 分类重新下载（64 位常用选 `x64-setup.exe`，ARM64 选 `arm64-setup.exe`），再重装后启动。系统为 Win7：官方已写明不再支持，无法按本方法确认可用程序。窗口长时间不出现：先核对自己安装的标签是否已包含「服务停止导致约两分钟才显示窗口」的修复；仍无窗口时，按发布说明把问题归到服务或内核启动，而不是更换非官方安装包。出现「program not found」或服务无法启动：核对该标签是否已修复该类问题；未修复则改用发布页上已写明修复的更新正式版标签，仍以官方包名为准。首次用管理员启动后内核被拒绝：对照 v2.5.5 关于数据目录所有权的说明，优先改用已记载修复的正式版标签。无法对应官方仓库时：停止使用当前文件，只从官方仓库指向的发布页获取 Windows 安装包。
